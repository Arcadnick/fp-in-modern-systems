## Запуск

Нужен Python 3.10 или новее, внешних зависимостей нет.

```bash
cd 02-seminar-stratified-design
python3 -m filmoteka
```

Пункт меню **3** загружает тестовые данные, пункт **1** — файл `data/films.txt`.

## Как строится граф вызовов

Граф не рисуется вручную: его строит [`diagrams/callgraph.py`](diagrams/callgraph.py)
по исходному коду (модуль `ast`), а слои задаются в
[`layers_before.py`](diagrams/layers_before.py) и [`layers_after.py`](diagrams/layers_after.py).

```bash
cd 02-seminar-stratified-design
python3 diagrams/callgraph.py filmoteka diagrams/layers_after.py diagrams/callgraph-after
dot -Tsvg diagrams/callgraph-after.dot -o diagrams/callgraph-after.svg
```

Для исходного состояния тот же скрипт запускается на коде коммита `f203ef0`.
Для SVG нужен Graphviz (`brew install graphviz`).

Скрипт также создаёт `callgraph-before-overview.svg` и `callgraph-after-overview.svg`
для слайдов 3 и 10: одна строка на слой, количество узлов по категориям,
связи соседних слоёв и прямые обходы из верхних слоёв к данным и языку.
Числа на стрелках — количество связей полного графа. Остальные связи
показаны только в полных `callgraph-before.svg` и `callgraph-after.svg`;
в HTML они открываются по клику на обзор. Обзоры не заменяют полный граф.


- **Узлы:** функции, методы, конструкторы и сеттеры свойств; поля сущностей
  и исключения — узлы данных; встроенные функции, методы `str`/`list`/`dict`,
  `for`, индекс и срез — слой «Язык Python».
- **Категории:** действие — функция, которая сама или через другие вызывает
  `input`, `print`, работу с файлами или часы; данные — поля и исключения;
  остальное — вычисления.
- **Слои:** полоса с назначением. Если функции одного слоя вызывают друг друга,
  слой делится на подуровни, поэтому все стрелки идут сверху вниз.
- **Неявные вызовы** (`str(film)` → `__str__`, `sorted` → `__lt__`, `len` и `for`
  по плейлисту) перечислены в файлах слоёв с комментариями.
- **Ограничения:** вложенные функции и лямбды относятся к функции, в которой
  написаны; полиморфный вызов идёт к методу базового класса.

После каждого изменения сценарий по всем 18 пунктам меню (1366 строк вывода)
давал побайтно тот же вывод, что и исходная версия. Сохранённый файл и удаление
дубликатов дополнительно сверены с исходной версией.

| Коммит | Изменение | Шаблон |
|---|---|---|
| `2a515f6` | 1. `calculations.py` разделён по уровням: `generic` (общие операции), `rules` (правила, на которые опираются классы), `queries` (запросы к спискам произведений), `records` (формат файла) | удобные слои |
| `f075070` | 2. `Playlist`: 21 метод → 9 (после изменения 3 — 8). Убраны 8 неиспользуемых методов из C#, остальное — через общие `sorted_with`, `replaced`, `unique_by` | минимальный интерфейс |
| `59210d1` | 3. Меню работает только через методы `Catalog`: `check_not_empty`, `film_at`, `viewer_names`, `recommendations_for`… Обращений к внутренностям извне: 22 → 0 | барьер абстракций |
| `c57e96c` | 4. Правила сравнения, таблица типов, фильтры и статистика (`Statistics` вместо словаря) опущены из команд в `queries` и каталог | простая реализация |
| `7676acd` | 5. Слой представления `views.py`: текст для экрана ушёл из классов (`details`, `describe`, `profile_lines`) и из команд | удобные слои |
| `efd2e4a` | 6. Формат файла — `records.py`: кортеж `FIELDS` и одна `to_record` вместо четырёх `__str__`; дубликаты и сортировка — по ключам `identity` и `by_title_and_year` вместо `__str__` и `__lt__` | минимальный интерфейс |
| `20ccbb3` | 7. `main.py` (399 строк) разделён: `console` (единственное место с `input`/`print`), `dialogs`, `commands`, `history`, `main` (34 строки) | простая реализация |
| `783099d` | 7, продолжение по графу: в командах нет `for`, `len` и `except RatingException` | простая реализация |

## Сравнение графов

| Показатель | До | После |
|---|---|---|
| Слоёв с назначением (вместе с языком) | 11 | 9 |
| Подуровней | 29 | 19 |
| Самая длинная стрелка между функциями, слоёв | 7 | 4 |
| Стрелок между функциями через 3 слоя и больше | 49 | 16 |
| Функций верхних слоёв, напрямую зависящих от данных и языка | 21 | 1 |
| Обращений к внутренностям каталога и плейлиста извне | 22 | 0 |
| Функций и методов | 143 | 175 |
| — из них действий | 33 | 52 |
| Стрелок | 486 | 501 |

Устранённые длинные стрелки: `writer` → `Cinematography.details` (7 слоёв),
`compare` → `better_of`, `choose_film` → `item_at`, `filter_films` → `genre_matches`,
`register_viewer` → `parse_genres` (по 6), а также зависимость вычислений
от `__str__` и `__lt__`. Осталась стрелка в 4 слоя от каталога к общим операциям
copy-on-write и одна функция верхнего слоя с конструкцией языка: `main.main`
берёт команду из таблицы по номеру.

**Выводы.** *Сопровождение:* устройство каталога меняется в одном классе, новый
тип произведения добавляется без правки меню, формат файла — только в `records.py`.
*Тестирование:* действия собраны в пяти модулях, `input` и `print` — только
в `console.py`, тексты экрана — чистые функции. *Переиспользование:* `generic`,
`console` и `history` не знают о фильмах. *Цена:* файлов 12 → 20 и больше мелких функций.

## Итоговая структура

| Слой | Модули | Категория |
|---|---|---|
| Приложение: цикл меню | `main.py` | действие |
| Сценарии меню | `commands.py` | действия |
| Операции | `Catalog` (барьер), `dialogs.py`, `storage.py`, `history.py`, `constructors.py` | каталог — вычисления; диалоги и файлы — действия |
| Строительные блоки | `views.py`, `records.py`, `console.py`, `Playlist`, `queries.py` | консоль — действия, остальное — вычисления |
| Сущности | `cinematography.py`, `viewer.py` | вычисления (copy-on-write) |
| Правила предметной области | `rules.py` | вычисления |
| Общие операции | `generic.py` | вычисления |
| Данные | поля сущностей, `Statistics`, `Comparison`, `exceptions.py` | данные |
